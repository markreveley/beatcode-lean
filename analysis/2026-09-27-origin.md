# Origin

## The question

The operator asked, of beatcode: is it realistic to restart development
from formal specifications in Lean, with code as an ephemeral
implementation detail? What defines the seam between the side where humans
must audit code and the side where they need not? Is formal verification
necessary as agent-written pull requests get rubber-stamped? Will
high-velocity AI-driven systems without it escape comprehension?

## What the spike found (summary; the full record is in beatcode)

Five of beatcode's modules were transcribed into Lean 4.34.1 in about four
agent-hours and audited by independent agents. Every golden vector the
project had became a kernel-checked theorem for the integer half of the
crate; the float half was reproduced bit-for-bit by Lean's runtime but
stays on the "test" side. Four findings shaped this repository:

1. **The seam is three conditions, not "code versus spec"**: a readable
   independent statement; a machine check with no escape hatch; a binary
   compiled from the checked definition. Everything else a human reads.
2. **Formalizing a transcript pins quirks, not intent.** beatcode's spec is
   partly a transcript of a prior implementation; the theorems that came
   out pin an accent velocity of 57 where the rule as a person reads it
   gives 58. Statements must be written before code, by a human.
3. **The Lean definitions were longer than the Rust they replaced**, so
   "code is ephemeral" is only true once a short statement layer is
   separated from the executable by a proof.
4. **No human read any theorem statement the spike produced.** The missing
   piece was not proof but an operator's way in.

## The methodology, derived

The operator's two prior repositories supplied the way in: socrates (a
type system for prose statements with a deterministic gate and
per-statement ratification) and rtr (a lifecycle for changes with
ratification over exact text at a commit, hashed). Neither is merged into
the other; they meet at three shared primitives — a pinned text, a
ratification act, an evidence record — and the repository is built from
the smallest unit of commitment upward. See README.md.
